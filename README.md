# HIGH & LOW — ブラウザ対戦版（初期版）

GitHub Pages + Supabase Free で公開するためのファイル一式です。**まだ実サーバーへ接続しての動作確認はしていません。** 公開前に必ず複数端末でテストしてください。

## 1. 必要なもの

- GitHubアカウント（無料）
- Supabaseアカウント（Freeプラン）
- Webブラウザ
- SupabaseのProject URLとPublishable Key（または従来のanon key）
- 課金・独自ドメイン・Node.jsのインストールは不要

## 2. Supabaseの準備

1. https://supabase.com/ から新しいプロジェクトを**Free**で作成。
2. Authentication → Providers/Sign In の設定から **Anonymous Sign-ins（匿名サインイン）** を有効化。
3. SQL Editorで `setup.sql` の全文を貼り付けて実行。専用の**新規プロジェクト**で行ってください。既存データは触らない設計ですが、テーブル名が衝突する場合は止まります。
4. Project Settings → API（画面の名称が変わる場合があります）から **Project URL** と **Publishable Key** または **anon key** をコピー。
5. `config.js` の `YOUR-PROJECT` と `YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY` を置き換えて保存。
6. **service_role key / secret key は絶対にGitHubへアップロードしないでください。**

## 3. GitHub Pagesに公開

1. GitHubで `high-low` などの名前の**Public**リポジトリを作る。
2. ZIPを解凍し、`index.html`、`style.css`、`app.js`、`config.js`、`README.md` をリポジトリのルートへアップロード。`setup.sql` はアップロード不要（公開しても秘密キーは含みません）。
3. Settings → Pages → Build and deployment → Sourceを **Deploy from a branch** にする。
4. Branch `main` / `(root)` を選んで Save。
5. 数分後に表示される `https://ユーザー名.github.io/high-low/` を開く。
6. 画面が読み込めたら、名前を入力し「新しいルームを作成」を押す。

## 4. 対戦方法

1. 主催者がルームを作成し、参加URLまたはルームコードを全員に共有。
2. 参加者は各自のブラウザで開き、名前入力・入室。
3. 主催者が「数字選択へ」を押す。初期上限は開始人数×20。
4. 各自が秘密の数字を入力して確定。
5. 主催者が「サイコロを振って開始」を押す。サーバーが1〜6の出目でランダム順を決定（同点は内部の抽選で順序決定）。
6. 手番の人は生存者を指名して数字を予想。ハイ・ロー・正解は自動判定。
7. 数字を当てられた人は脱落。そのセットは生存者の手番だけで4周実施。最後の1人になったら即終了。
8. 4周終了時点で2人以上生存なら主催者が次のセットへ。脱落が1人以上いた場合のみ上限を半減（端数切り上げ）。数字は全員再選択。
9. 最後まで残った1人が優勝。

## 5. 注意点・初期版の制限

- 画面の状態は**2秒ごとの自動更新**で共有されます（WebSocketではなくポーリング）。
- 主催者が退出すると、別の人が主催者になる機能は**未実装**です。主催者は最後まで同じブラウザを使ってください。
- 同じブラウザの複数タブは原則同一ユーザーです。複数人テストは別ブラウザ・プライベートウィンドウ・別端末で行います。
- 匿名認証はブラウザのデータを削除すると元の参加者として戻れなくなる場合があります。
- 参加者が突然オフラインになったときの代理操作・強制退室・再接続救済は未実装です。
- ダイスが同じ出目の場合、実際に振り直す演出ではなく内部乱数で同点の順序を決める**簡略版**です。
- URLにはルームコードが含まれます。コードを知っている人が公開前のルームに参加できます。招待制を厳格にする機能はありません。
- Supabase Freeでは利用制限があり、非アクティブなプロジェクトは停止されることがあります。イベント前に起動確認をしてください。
- 公開される`config.js`のクライアント用キーは公開前提ですが、SQLによるアクセス制御を削除すると秘密の数字が漏れる危険があります。

## 6. 4人でのテスト項目

- [ ] 4つの異なるブラウザ/端末から参加できる
- [ ] 初期数字上限が80になる
- [ ] 他人の数字が画面に表示されない
- [ ] 自分の手番以外に予想できない
- [ ] HIGH、LOW、CORRECTの判定が合っている
- [ ] 正解後に脱落した人は次の手番に入らない
- [ ] 4周終了後に次セットを開始できる
- [ ] 脱落があれば80→40、脱落なしなら80のまま
- [ ] 最後の1人になったらゲームが終了する

## 7. 更新方法

GitHub上で `index.html`、`style.css`、`app.js` を更新するとPagesへ反映されます。SQLの修正はSupabase SQL Editorで別途実施してください。**現時点では初期版**なので、運用前に試験が必要です。
